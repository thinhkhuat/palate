Single definition in `open-taste-blueprint.md` §0/§9 + `plans/.../plan.md:Goals/Phases`. | 2026-08-15 |
| 5 | **ZCode adapter = hook-based learning, not a Claude Code byte-copy** | 4 events (`SessionStart`/`UserPromptSubmit`/`PostToolUse`/`Stop`); config in `.zcode/config.json` (workspace) or `~/.zcode/cli/config.json` (global) under `hooks.events.*` with `hooks.enabled: true`; strict-JSON hook output via `palate hook session-start`; `UserPromptSubmit`/`SessionStart` diff `.palate/model_edits.json` state against disk (Stop re-baselines it — row 11) | ZCode's contract differs where it hurts: config-file hooks are disabled by default, there is no `PreCompact` event, and non-JSON stdout marks the hook failed. No live harness sends a `files[]` Stop payload, so user_diff must be state-driven. Verified against the official zcode-guide v0.1.0 `diagnosing-hooks` doc; evidence in `docs/adapters/verification.md`. | 2026-08-28 |
| 6 | **Contradictions weaken + conflict, never silently coexist** | Negation/antonym detection with same-category scan; old row weakened, `conflicts` row opened, loser hidden / winner shown; `recall --include-conflicted` reveals | Without this the learner only ever reinforces and stale taste accumulates side-by-side in TASTE.md. Fixed 2026-09-04 (F2); evidence `plans/reports/fix-report.md`. | 2026-09-04 |
| 7 | **`internal/sync` removed** | Deleted `internal/sync/` (engine, encryption, test), `docs/sync.md`, and the `golang.org/x/crypto` dependency; `palate push`/`pull` keep their `TASTE.md` render/reimport behaviour | Zero callers outside its own test, no server, no config; the cursor (`PullChanges` bound one timestamp to both `created_at` and `id`) and the event-id model (string id vs `INTEGER PRIMARY KEY`) did not match the schema, and encryption was never invoked. Wiring it meant a rewrite, not a hook-up. Git history keeps the code if multi-device sync returns to the roadmap. | 2026-09-12 |
| 8 | **LLM taste distiller: env-only gateway, `llm_distilled` reuses existing confidence math** | A new `internal/distill` package calls an LLM on the user's own OpenAI-compatible gateway (`PALATE_LLM_ENDPOINT`/`PALATE_LLM_MODEL`/`PALATE_LLM_API_KEY`, env-only — never in `config.yaml`) to turn live sessions, historical transcripts (8 readers), git history, and memsearch journals into `llm_distilled` signals. They flow through the existing `learn.ApplySignal` — same decay/reinforce/weaken math, same `preferences` table, same `TASTE.md` render, same `safety.Scan` gate — landing at a new `trust_tier=DISTILLED`, distinct from user-typed `STATED` rows. `distill.mode: auto\|review` in `config.yaml` picks automatic apply vs. a human-approval queue. No `PALATE_LLM_*` set = the distiller is silently off; today's regex/verbatim paths are unchanged. | Regex-matched "I prefer…" phrases and verbatim added-lines diffs are shallow and can store conversational noise or raw code as a "preference"; Command Code's own taste feature proves an LLM-summarized alternative works. Reusing Palate's confidence engine (rather than a parallel one) keeps decay, contradiction detection, and rendering identical across every signal source. See `plans/260912-2316-llm-taste-distiller/plan.md`. | 2026-09-12 |
| 9 | **Plugin packaging: dual manifest set, `hooks/hooks.json` shared SSOT** | One installable plugin sourced directly from the repo (`source: "./"`) for both Claude Code (`.claude-plugin/`) and Codex (`.codex-plugin/`), instead of the manual `palate hook install` + per-harness MCP config wiring. `hooks/hooks.json` is generated from `adapters.GenerateClaudeCodeHooks` (drift-checked by a Go test, not hand-maintained); each harness gets its own MCP descriptor (`.mcp.json` `${CLAUDE_PLUGIN_ROOT}`-rooted vs `.codex-plugin/mcp.json` relative `cwd:"."`) because Codex expands `${CLAUDE_PLUGIN_ROOT}` in hooks but never in `mcpServers` (upstream `openai/codex#35762`); the Codex manifest carries no `hooks` field because its validator rejects one. A fail-open POSIX `bin/palate` launcher (`PALATE_BIN` → staged binary → `PATH` → locked local `go build` → one stderr line) resolves the binary without requiring a preinstall. | Layout and every named risk are lifted from the user's own working dual-harness plugin, `skill-concierge` (`~/in-PROD/MY-WORKBENCH/skill-concierge/`, read directly 2026-09-12) — not reinvented. `palate hook install` stays for Command Code, ZCode, and no-plugin setups, which have no plugin system here. See `plans/260912-2316-llm-taste-distiller/phase-07-plugin-packaging-claude-code-and-codex.md`. | 2026-09-13 |
| 10 | **Launcher plugin root: resolved from `$0`, harness env vars are a validated fallback only** | `bin/palate` derives `plugin_root` from its own file location; `CLAUDE_PLUGIN_ROOT` / `ZCODE_PLUGIN_ROOT` are consulted only when `$0` yields no `bin/palate`, and only when the candidate is an absolute path that really contains `bin/palate`. The `go build` fallback additionally requires `go.mod` at that root. The fail-open line names the real reason (no go / no source tree / build failed). | Trusting the env var first broke on a real host: Claude's `settings.json` env carried the literal, unexpanded `CLAUDE_PLUGIN_ROOT="$HOME/.claude"` into every spawned process (a deliberate hookify workaround, not debris — see skill-concierge `docs/caveats.md` §20), so the launcher created `./$HOME/.claude/.cache` in the caller's cwd and reported "go is not installed" with go present; only a `palate` on `PATH` masked it. Same rule as skill-concierge's launcher (`bin/skill-search-mcp` self-locates via `BASH_SOURCE`) and its ADR-0034 "skip falsy/non-absolute candidates". Pinned by `scripts/verify-plugin-launcher.sh` cases 4–7 (own-tree build, literal root, foreign valid root, truthful message). | 2026-09-13 |
| 11 | **`user_diff` is learned at UserPromptSubmit / SessionStart, never at Stop** | `hook stop` re-baselines every `model_edits.json` snapshot to the bytes on disk (`refreshModelEdits`); `hook user-prompt` runs the same state walk SessionStart already ran (`handleStateWalkUserDiffs`) before capturing a stated preference. The scripted `files[]` Stop payload (explicit `hash_after` callers) is unchanged. | Stop fires while the assistant still owns the turn, so drift between a PostToolUse snapshot and disk at that moment is the assistant's own follow-up edit (sed/python via Bash after an Edit/Write), not a hand-edit. Observed 2026-09-13: three `user_diff` "preferences" quoting the agent's own report and script text were learned at 17:01/17:06 and injected into every session prewarm. The user only holds the keyboard between Stop and the next UserPromptSubmit (or across sessions), so those are the only honest comparison points. Pinned by `TestHooksDoNotSpawnWhenUnconfigured` (Stop learns nothing and re-baselines; UserPromptSubmit learns). `setupTempProject` now blanks `PALATE_LLM_*` so the suite is hermetic on hosts that export a gateway. | 2026-09-13 |
| 12 | **One durable home — `~/.claude/palate/`, `PALATE_HOME` override, global by default, legacy per-repo by detection** | `config.ResolveHome` is the single resolver: `PALATE_HOME` > `home:` in `./config.yaml` > an existing `./.palate/palate.db` (legacy) > `~/.claude/palate`. Every path derives from it (`palate.db`, `state/` for hook snapshots/recovery/lock, `TASTE.md`, `backups/`, `skills/`, `skill-candidates/`, `config.yaml` seeded once from the embedded default). Relative/`~` values are made absolute once at load. The CLI and the MCP server share `config.Resolve`. | The user's own convention (skill-concierge ADR-0025 §5 / ADR-0033): one operator-owned home under `~/.claude/<tool>/` shared by every harness, one `<TOOL>_HOME` override resolved in one place, seed-if-missing, dated backups — and Command Code parity, whose taste is machine-wide. Per-repo stores meant taste learned in one project never reached another. Legacy detection keeps 0.1.x installs working with no flag; `palate migrate` moves such a store into the home losslessly (a TASTE.md round-trip would flatten every row to `IMPORTED 0.4`, which is what happened on the first manual migration on 2026-09-13 and was reverted from backup). Pinned by `internal/config` precedence tests, `cmd/palate/home_test.go`, and both `scripts/verify-plugin-*.sh` running global + legacy passes. | 2026-09-13 |
| 13 | **`TASTE.md` is auto-maintained after every write (supersedes the push-only reading of REQ-004)** | `storage.AppendEvent` — the single funnel every mutation passes through — marks the store dirty; `storage.Close` (every CLI verb, hook and the detached distiller) and `storage.FlushIfDirty` (after each MCP write tool, via `flushed()`) re-render `<home>/TASTE.md` through a callback the CLI/MCP register (`render.Sync`, compare-before-write). Header carries the last event id; each bullet ends with `(source, TRUST_TIER)`. `render.auto: false` / `PALATE_RENDER_AUTO=0` turns it off; `push`/`pull` unchanged; `lint` defaults to the auto file. | A SQLite file is not reviewable; Command Code keeps `~/.commandcode/taste/taste.md` current and human-readable. REQ-004's "lossy render, not the truth" still holds — the events log stays authoritative — only the "render on push" half is retired. One funnel means a new code path cannot forget to render. Pinned by `internal/storage/dirty_test.go`, `internal/render` header/no-rewrite tests, `cmd/palate/auto_taste_test.go`, `internal/mcp` `TestAutoTasteAfterMCPPrefer`. | 2026-09-13 |
